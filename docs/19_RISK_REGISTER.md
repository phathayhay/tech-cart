## 1. Risk Assessment Matrix

| Risk ID | Category | Risk Description | Likelihood | Impact | Severity | Mitigation Strategy & Controls |
| :--- | :--- | :--- | :---: | :---: | :---: | :--- |
| **RISK-01** | **Concurrency & Inventory** | **Flash-Sale Overselling or Database Deadlocks:** Multiple buyers concurrently checking out overlapping SKUs cause negative available stock or circular row-lock deadlocks. | High | Critical | **CRITICAL** | 1. Sort all cart `variant_id`s ascending (`ORDER BY variant_id ASC`) before executing `SELECT ... FOR UPDATE`.<br>2. Enforce PostgreSQL `CHECK (quantity_on_hand >= quantity_reserved AND quantity_reserved >= 0)` at the database engine level.<br>3. Verify with automated `concurrent-checkout.e2e-spec.ts`. |
| **RISK-02** | **Financial Integrity** | **Floating-Point Rounding Discrepancies:** Using JS `number` or SQL `DOUBLE PRECISION` causes $0.01$ mismatches between order `grand_total` and payment gateway webhook amounts. | High | Critical | **CRITICAL** | 1. Replace all legacy `DOUBLE PRECISION` columns with `DECIMAL(15, 2)` in PostgreSQL.<br>2. Perform all subtotal, voucher, pro-rata line allocation, and tax math using `Prisma.Decimal` helpers (`money.util.ts`). |
| **RISK-03** | **AI Assistant Reliability** | **AI Hallucination of Prices, Discounts, or Stock:** LLM invents nonexistent promo codes or quotes outdated prices, creating customer disputes. | Medium | High | **HIGH** | 1. System prompt strictly forbids answering product/price/stock/policy questions without calling a backend tool.<br>2. Render authoritative prices and stock badges directly inside structured `ui_cards` generated by the backend `ToolExecutorService` (bypassing LLM text formatting for the card UI). |
| **RISK-04** | **AI Security & Privacy** | **Prompt Injection / Cross-User Order Leakage (IDOR):** Malicious user prompts AI to reveal another customer's order details or system secrets. | Medium | Critical | **HIGH** | 1. Never accept `user_id` as an LLM-supplied tool parameter; inject `verifiedUserContext.userId` from the verified JWT inside `ToolExecutorService`.<br>2. Sanitize user messages and enforce read-only DB access on catalog tools. |
| **RISK-05** | **AI Cost & Latency** | **Token Wallet Exhaustion / LLM Outage:** Bot traffic or long chat histories spike Gemini API costs, or Gemini outage stalls the backend. | Medium | Medium | **MEDIUM** | 1. Cap chat context to the last 10 messages and max 3 tool turns.<br>2. Enforce `@nestjs/throttler` rate limits (`15 req/min/user`) and daily USD budget cap (`AI_DAILY_MAX_COST_USD`).<br>3. Apply an `8,000ms` timeout with graceful fallback to keyword search cards. |
| **RISK-06** | **Payment & Stock Lockup** | **Inventory Hoarding via Unpaid Orders:** Attackers or abandoned checkouts lock up `quantity_reserved` indefinitely on online payment orders. | Medium | High | **HIGH** | 1. Set `reservation_expires_at = NOW() + INTERVAL '15 minutes'` on every online-payment order.<br>2. Run a scheduled background job every 60 seconds to cancel expired `UNPAID` orders and release `quantity_reserved`. |
| **RISK-07** | **Payment Security** | **Webhook Spoofing or Replay Attacks:** Attacker sends fake payment success payload or gateway retries the same webhook multiple times. | Medium | Critical | **HIGH** | 1. Verify cryptographic `HMAC-SHA256/SHA512` signature against raw body.<br>2. Enforce `UNIQUE (provider_transaction_id)` in `payment_transactions` inside an ACID transaction. |
| **RISK-08** | **Architecture Migration** | **Regression of Existing Features During Express $\rightarrow$ NestJS & Vanilla JS $\rightarrow$ React Migration:** Losing the working 360° Rotating Wheel UX, Cloudinary upload pipeline, or existing user passwords. | Medium | Medium | **MEDIUM** | 1. Port the exact trigonometric 360° Wheel logic (`store-wheel.js` / `store-wheel.css`) into `<ProductWheelShowcase />` and verify with Playwright E2E.<br>2. Reuse verified `.env` PostgreSQL & Cloudinary settings.<br>3. Implement transparent `SHA-256` $\rightarrow$ `bcrypt` password re-hashing on login. |
